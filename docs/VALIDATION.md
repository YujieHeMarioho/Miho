# Miho 验证记录

验证日期：2026-09-30 至 2026-10-01（Asia/Shanghai）。环境：Apple Silicon、macOS 27.0、Xcode 16.1。

## v0.6.0 · 实际节拍模型与连续律动

前版被用户指出快节奏说唱、hip hop 和 rock 跟随不佳。这是新的实现与验证记录，旧版测试通过不代表该观感问题已通过验收。

- 真正接入 BeatNet model-2 CRNN；权重与转换图固定校验和，图随仓库／应用分发。上游滤波器与生成的 136 个滤波器逐项一致；30 个连续状态帧的 PyTorch／ONNX 输出差异低于 2e-6；原生 1411 点 FFT、特征和递归输出与独立 Python 结果一致，重置后可复现。
- `./scripts/test.sh -c release`：**58 项 XCTest 全部通过**。新增 88／124／174 BPM 解码、碎拍／短填充不改速度、半拍错位恢复、持续说唱不抑制律动、暂停回落，以及最终身体点头对拍和速度／加速度边界。
- 最终姿态对拍测试中，三个速度的连续点头峰值与预设拍子的偏差小于 100 ms。此测试输入是合成的节拍概率，不能代表真实歌曲识别精度或完整声音到显示延迟。
- 自写身体轨迹共享学到的相位；相位提前补偿惯性，快歌身体起伏可取半速，躯干点头保持每个跟踪到的拍子；换重心取更慢的两拍周期。人声独立叠加，不按预置舞步定时切换。
- Release `.app` 构建、`codesign --verify --deep --strict` 通过；运行库路径只含相对应用路径。使用打包的应用直接分析音频文件，确认两份模型和 SDK 可从应用内加载。

文件样例使用完整的两个原生模型与姿态引擎；不播放、不上传，也不录制系统声音：

| 样例 | 结果与证据边界 |

上述置信度占比是**模型支持状态的持续时间，不是节拍准确率**。Choice 中后段的强模型峰与跟踪相位的中位偏差约 43 ms，参照点仍是模型自身输出，不能代替人工歌曲拍点标注。

- 从实际 BeatNet 模型分析本项目合成鼓点生成 360 帧／12 秒预览，检查最终 3D 渲染，README 标明其输入和证据范围。
- 本机已启动 v0.6.0，捕获和两份模型正常连接；当时没有正在播放的声音，静音时未发明拍子，分析一段 512 帧回调通常约 4–7 ms。仍保留原角色搭配与 0.8× 动作幅度。
- **本次实体快歌观感验收未完成**：电脑锁屏，自动操作工具不能解锁。已请用户解锁并提供一首上一版失败的快歌，尚未收到回复；没有操作播放器或把 rap／rock 实听记成通过。新版已运行，解锁后可打开舞步预览测试。
- 原来的权限、设备重连和休眠恢复逻辑未变，回归测试通过；实体设备切换仍待用户反馈，不扩大历史硬件结论。完整声音到显示延迟 <150 ms 仍是目标，未用文件推理速度冒充端到端实测。

## v0.5.0 · 本机人声分离与连续唱腔姿态

分支：`feat/miho-3d-dance`。此前循环舞步和混音谐波代理方案被用户否定，本版替换这条路径。

- 固定版本的 StemgenRT-5.8 ONNX 图通过原生 ORT 1.26.0 CPU 宿主运行。系统 Tap 改为立体声，分析路径重采样至 44.1 kHz，保留全部八份状态，首跳预热。播放端没有改变。
- 人声、鼓点分别分析；没有把混音频段当作独立人声。源码和模型仍可能漏入伴奏，测试不等于完美分离。
- 删除四套舞步、八拍换风格、自动组合和周期摇摆。唱句的姿态保持至真实收句，重音回到当前唱腔姿态。
- 独立后台队列；约 60 ms 待处理容量。积压时丢弃旧音频、重置模型和事件代次，取消时不发布旧结果。音频不写文件。
- Release XCTest：50 项全部通过；此前 Debug 的 48 项也通过，包括原生模型与官方 Python 宿主的固定输入一致性、状态重置、源顺序、44.1/48/96 kHz 重采样、积压与取消、长音保持五秒、渐弱不落回待机、短暂分析重置不反向、连续上扬后保持、音高回落、鼓点不打断长音、punch 回到长音姿态、速度／加速度约束，以及现有场景、手势和生命周期回归。另有从实际分析器到姿态的十秒合成唱句测试，验证上扬后保持至真实结束。
- 完整分析链 Debug 实测约 1.04 秒处理 1.07 秒音频；Release 实测约 0.46 秒处理同样的 1.07 秒音频。C++ 单独推理的 1,000 跳测试平均约 1.18 ms、p95 约 1.50 ms、p99 约 1.84 ms，128 样本音频时长为 2.90 ms；峰值约 3.16 ms，因此仍需要队列和丢弃恢复。
- Release 构建、原生图标导出和严格本地签名通过。模型、库和 MIT 许可均在 `.app` 内；应用二进制不保留仓库的运行库绝对路径。
- 网易云音乐《小孩》（罗森涛）实际播放：分离后的能量、周期性、音高、延音和姿态随输入变化，当前粉色搭配及 0.8× 动作幅度保留，预览不再出现四种舞步按钮。
- 首次运行诊断出现约 198 ms 的捕获时间戳到姿态峰值，未将它记作低于 150 ms。再次运行同时查看分段耗时：512 样本输入缓冲约 10.7 ms；后台分析通常约 5 ms，偶有排队峰值和状态重置；该次运行最大姿态时间约 135 ms。此项不包含 SceneKit 与显示扫描，不代表完整听觉到画面延迟。
- 最终版本预览确认人声／鼓点／延音状态；实际点击暂停后分析停止，恢复后再次连接并显示长音保持。该次最终运行的诊断峰值约 129 ms，同样不含显示延迟。
- 更新离线预览为 300 帧／10 秒的合成唱句，明确标注它绕过源分离，不作为真实歌曲分离质量证据。
- 未获得用户指定歌名／时间段的回复，也没有真实歌曲逐句标注或用户的最终观感验收；不宣称全曲对拍或歌声跟随准确率。

## v0.3.0 · 球形、清晰轮廓与角色编辑器

分支：`feat/miho-3d-dance`。

- 默认身体改为三轴半径均为 0.84 的真实球体，移除桌面尺寸下产生颗粒感的细绒毛网格；使用 96 分段球体、平滑材质、关闭屏幕空间环境遮蔽噪点，桌面开启 8× MSAA。棕色耳机与黑墨镜保留。
- 普通拖动旋转，Option 拖动换位置；双击回正。松手有阻尼惯性，默认停留在该角度，可开启自动回正。
- 实际桌面拖动后可见侧面／背面，位置仍为 (86, 885)，确认没有同时移动窗口；双击后恢复正面。截图检查新的蓝色球体轮廓，无此前绒毛带来的颗粒。
- 自动化工具对非激活窗口的点击附带 Command 修饰键，因此换位置使用 Option，不把自动化附带的 Command 当作移动操作。原生事件分支另有回归测试。
- 打开「自定义角色」，实际检查 790 × 650 窗口、完整的名字、形态、颜色、眼睛、眼镜与配饰控制，配饰区域通过滚动显示。观察桌面同步显示紫色搭配，保留当前选择。
- 自定义外观保存于本机 UserDefaults；舞步预览也使用同一搭配。材质换色与形态改变不重置鼠标角度。
- 自定义分类核对 [Dots 官方说明](https://learn.chatgpt.com/docs/dots)。官方没有公布完整款式／几何目录，当前款式是本项目的程序化 3D 实现，不把它标记为 OpenAI 全部选项的原样复制。
- `./scripts/test.sh`：37 项 XCTest 全部通过。包含 7 项分析、9 项编舞、5 项旋转、3 项搭配编码、5 项场景和 8 项模型／生命周期测试。
- 新测试覆盖完整横向旋转、俯仰边界、异常拖动、惯性、自动回正、保留角度、手势路由、默认身体深度、各种配件／眼镜重建、实际合并耳机网格换色、只换色时复用身体几何、外观持久化、恢复和与舞步同时应用。
- Release 构建、图标导出和本地严格签名检查通过。实体 Option 拖动和完整硬件组合仍由手动设备验证补充，未扩大历史硬件验收结论。
