# Miho 验证记录

验证日期：2026-09-30 至 2026-10-01（Asia/Shanghai）。环境：Apple Silicon、macOS 27.0、Xcode 16.1。

## v0.3.0 · 球形、清晰轮廓与角色编辑器

分支：`feat/miho-3d-dance`。

- 默认身体改为三轴半径均为 0.84 的真实球体，移除桌面尺寸下产生颗粒感的细绒毛网格；使用 96 分段球体、平滑材质、关闭屏幕空间环境遮蔽噪点，桌面开启 8× MSAA。棕色耳机与黑墨镜保留。
- 普通拖动旋转，Option 拖动换位置；双击回正。松手有阻尼惯性，默认停留在该角度，可开启自动回正。
- 实际桌面拖动后可见侧面／背面，位置仍为 (86, 885)，确认没有同时移动窗口；双击后恢复正面。截图检查新的蓝色球体轮廓，无此前绒毛带来的颗粒。
- 自动化工具对非激活窗口的点击附带 Command 修饰键，因此换位置使用 Option，不把自动化附带的 Command 当作移动操作。原生事件分支另有回归测试。
- 打开「自定义角色」，实际检查 790 × 650 窗口、完整的名字、形态、颜色、眼睛、眼镜与配饰控制，配饰区域通过滚动显示。观察桌面同步显示紫色搭配，保留当前选择。
- 自定义外观保存于本机 UserDefaults；舞步预览也使用同一搭配。材质换色与形态改变不重置鼠标角度。
- 自定义分类核对 [Dots 官方说明](https://learn.chatgpt.com/docs/dots)。官方没有公布完整款式／几何目录，当前款式是本项目的程序化 3D 实现，不把它标记为 OpenAI 全部选项的原样复制。
- `./scripts/test.sh`：37 项 XCTest 全部通过。包含 7 项分析、9 项编舞、5 项旋转、3 项搭配编码、5 项场景和 8 项模型／生命周期测试。
- 新测试覆盖完整横向旋转、俯仰边界、异常拖动、惯性、自动回正、保留角度、手势路由、默认身体深度、各种配件／眼镜重建、实际合并耳机网格换色、只换色时复用身体几何、外观持久化、恢复和与舞步同时应用。
- Release 构建、图标导出和本地严格签名检查通过。实体 Option 拖动和完整硬件组合仍由手动设备验证补充，未扩大历史硬件验收结论。

- 耳机回归测试防止合并网格时重复加入父节点位移，使耳机悬在身体上方。
- Release `.app` 构建与本地签名验证通过。窗口调整为 220 × 260 点，蓝色身体约 140 点宽。
- 本版最初构建时 Mac 锁屏，随后解锁并启动验证了桌面显示与声音响应；一次运行收到 9,624 次回调、1,373 次有声回调和 30 个鼓点，捕获帧到动作状态最大约 21 ms。此统计不包含完整感知延迟。当前鼠标旋转与新版外观验证见 v0.3.0。

- 系统输出播放本地合成的低频鼓点、持续和弦与高频瞬态，桌面状态从等待声音切换到活力舞步，并在脚跟脚尖、手臂 Wave、身体波浪等动作之间轮换。

- 检查预览后调低了过亮的灯光，扩大站姿并调整脚尖方向，避免球鞋相交；动作力度同时影响全身姿态幅度。
- 将高频姿态发布与设置／诊断 UI 分开，设置和诊断不再随每个动画帧重排。

“情绪”仅是声音特征推导的动作状态。未验证歌词／歌曲情感识别，因为本版不包含这类识别。

## v0.1 · 基础版历史记录

## 自动验证

`./scripts/test.sh`：13 项 XCTest 全部通过。

- 静音不产生动作能量或鼓点；人声频段能驱动律动。
- 音量与灵敏度提升会增大动作；持续音不会连续误触发弹跳。
- 四个间隔低频脉冲检测到四个鼓点。
- 停止声音一秒内能量回落到待机阈值。
- 44.1 / 48 / 96 kHz 采样率的首个强鼓点在分析器内 20 ms 内响应。
- 非有限样本不会污染输出。
- 捕获权限失败时仍保留模型，可重试；测试使用模拟捕获器，不改变系统权限。
- 设备变化合并为一次重连；暂停取消待执行的重连。
- 暂停后的唤醒不会恢复捕获；退出会取消待执行的重连。
- 休眠停止捕获，唤醒重连；通过发送系统通知验证控制逻辑，没有实际让整台电脑休眠。
- 灵敏度可持久化并传给捕获器。

`./scripts/build-app.sh`：Release 构建、原生角色图标生成与 `codesign --verify --strict` 通过。

## 本机运行验证

- 真实系统音频捕获正常：音乐软件网易云音乐播放时可见音符、摇摆与张嘴。
- 本地合成鼓点 WAV 用 `afplay` 播放，通过系统声音捕获驱动分析；同时有音乐软件声音时仍能工作。
- 改为不包含任何硬件子设备的 Tap-only 聚合后，十秒诊断收到 952 次回调、952 次有声回调及 13 个鼓点。该次测试为混合输出，不作为单首音乐节拍准确率测量。
- 停止播放后观察到「等待声音」与待机表情。
- 右键菜单暂停后显示「已暂停」，恢复后重新收到声音。
- 灵敏度滑块从 1.0× 调到 1.1×，再恢复到 1.0×。
- 拖动后持久化位置由 (2336, 71) 变为 (2266, 151)。
- Chrome 中播放 YouTube 视频时，Miho 显示正在跳舞；关闭临时视频标签后恢复「等待声音」。
- 隐藏精灵后窗口消失；重新打开应用会显示原精灵窗口。
- macOS 设置确认 Miho 使用「仅系统音频录制」权限；测试设备当前为 AirPods。
- 新增时间诊断后，十秒实测收到 862 次回调、862 次有声回调及 16 个鼓点，捕获帧到动作状态最大为 21.402625 ms。这不是完整扬声器到画面端延迟。

## 尚需扩展的设备验证

- 实体蓝牙／有线耳机切换、实际整机休眠唤醒、多显示器拔插与全屏应用共存。
- 不同设备上完整的播放端到画面端延迟。捕获帧到动作状态的统计用于定位内部延迟，不包括全部音频输出、显示扫描与感知链路。
- macOS 14.2 的实体设备兼容性；最低系统版本来自 Apple API availability，当前实测系统为 macOS 27.0。

上述限制不应解读为已完成所有硬件组合的兼容认证。
