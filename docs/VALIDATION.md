# Miho 验证记录

验证日期：2026-09-30 至 2026-10-02（Asia/Shanghai）。环境：Apple Silicon、macOS 27.0、Xcode 16.1。

## v0.10.0 · 两种跟随模式与贴边频谱柔光

用户要求将人声与背景音乐分成两种可选模式，增加歌手模式的动作变化，并让高低频形成紧贴角色边缘的柔光波峰。

- 歌手模式以真实人声起音交替转向，并将音量、可靠音高变化映射到点头、转肩、侧倾和换重心；减小只向前拉伸的比重。长音保持当前目标，不因经过几秒就强制返回，也不运行伴奏循环。
- 音乐模式使用鼓声、低频和混音力度，以及实际 BeatNet 的节拍相位；连续点头、弹动和较慢的换重心通过同一受限惯性求解器，重拍有限加力。快节奏身体可取半速，避免碎高频连续触发全身冲击。
- 两种模式可从右键／菜单栏或预览切换，选择持久化；切换不重启捕获、不重建角色外观、不跳回默认姿态。
- 删除 Canvas 圆环，八层实际角色网格沿法线外扩，高斯透明度与视角羽化产生贴边柔光。身体、耳朵、耳机等轮廓随外观和鼠标旋转同步；24 段真实频谱产生局部波峰，低频和重音进一步外扩。频段与颜色在角度接缝处连续；歌手模式使用人声频谱，音乐模式使用混音频谱。
- Release XCTest：**76 项全部通过**（约 6.77 秒）；最后的光晕颜色／接缝／羽化调整后，**7 项原生场景测试再次通过**（约 1.03 秒）。GPU 实际渲染验证低／高频输出不同、柔光像素距真实角色轮廓小于 24 像素、低透明度仍保留颜色，以及旋转后轮廓改变。另覆盖歌手多轴动作与长音、无人声音乐律动、模式保存与切换连续性、88／124／174 BPM 的最终点头、模型宿主和生命周期回归。
- 本机初次打开预览时播放器暂停，诊断前 60 秒没有输入；没有把该段记成音乐响应。随后通过网易云菜单播放当前《Marry》（Top Barry），未选择新曲目或调整音量。实际预览确认「正在跟随人声」、切到「正在跟随鼓点与音乐」及「鼓点律动／重音发力」，再切回歌手模式正常继续。连接状态显示 17,134 次回调、17,035 次有声回调，本机模型已连接，单次处理约 1.1 ms，内部捕获时间戳到姿态早期峰值约 74 ms；后台构建／导出期间后续累计峰值达到 243 ms，没有隔离原因，不能把早期值当作稳定延迟。
- 用户当前实际外观为紫色，幅度 1.5×、灵敏度 1.4× 保留。早先记录的粉色搭配不作为本次实际外观。
- 导出并检查两种模式各 300 帧／10 秒的合成动画，以及深色和浅色背景的原生 PNG；波峰局部外扩、边缘淡出，无外部大圆环。歌手演示经过实际元音特征分析，音乐演示额外经过实际 BeatNet；合成输入直接提供各声部，绕过人声分离，不作为实际歌曲分离质量证据。
- v0.10.0 / build 13 Release 构建与深度严格本地签名通过。实际预览中发现淡出轮廓发白，修正颜色后通过菜单退出测试实例、备份并替换最终应用；最终只有一个 `dist/Miho.app` 实例运行。没有额外权限请求。最终实例恢复用户保存的音乐模式；测试期间用户也在预览切换歌手／音乐模式，继续保留当前选择。
- 最终实例的 60 秒本地标量诊断共 590 次采样，其中音乐模式 246 次、歌手模式 344 次，588 次模型就绪；人声能量 0.008–0.652，转肩 -0.351–0.325、点头 -0.089–0.211、整体缩放 1–1.190、选定频谱最大值 0–0.992。分析耗时 3.3–58.5 ms，内部捕获时间戳到姿态累计峰值 **152.4 ms**，未包括显示延迟，不能宣布端到端 <150 ms 已完成。测试结束后通过播放器菜单恢复原来的暂停状态，保留 Miho 与模式预览运行。

真实歌曲的观感仍需用户试听；本次连接与渲染检查不代表逐句跟随准确率、完整端到端低于 150 ms 或实体输出设备切换验收。人声分离可能泄漏伴奏，音乐节拍可能失锁或采用半速解释。没有保存或上传现场声音。

## v0.9.0 · 只跟人声与透明环形音波

用户提供环形播放器参考图，明确取消外部方框及鼓点／延音的独立动作。当前人声再次增强时继续抬高，变轻就收小；相同音量与音高保持同一目标，不用唱句时长产生额外舒展动画。

- 从 `Choreographer` 删除鼓点冲击、伴奏相位循环与混音能量控制；人声重音的冲击力度也乘以当前人声音量驱动。保留受限惯性、真实新唱句方向和可靠音高变化。
- `SoundField` 仅传递当前人声包络与 24 段人声频谱，删除鼓声、混音频谱、96 点滚动历史。Canvas 用周期三次曲线画一圈浅蓝／淡紫音波，桌面没有底板、矩形边框、网格或线图。
- 圆环随同一姿态的中心和等比缩放变化，周围透明留白包含耳机。窗口改为 280 × 300 点，镜头调整后保持近似原角色显示大小，不影响拖动、旋转和保存的搭配。
- Release XCTest：**69 项全部通过**。同一人声在强鼓点、快伴奏、满量程混音频谱下，逐帧完整姿态和音波完全相同；无人声的 88／124／174 BPM 伴奏与静音姿态相同。连续三档人声增强能继续抬高，减弱平滑回落；保留真实元音起音响应、长音／音高、配饰、暂停、捕获代次与设备恢复检查。
- Release `.app` v0.9.0 / build 12 构建完成，`codesign --verify --deep --strict` 通过。导出并检查 300 帧／10 秒合成预览和直接渲染的 PNG；圆环完整围住角色与耳机，大小声有可见差别。合成预览直接提供独立声部，不作为真实歌曲分离准确率证据。
- 更新时进程检查最初误把检查命令自身当作 Miho 进程，替换未执行且误开了一次旧版；已通过菜单退出并纠正检查，仅在安装和版本核验成功后启动新版。旧 `.app` 留在忽略的 `dist/previous/` 备份目录，最终只有一个 v0.9 实例运行。
- 实际桌面与预览确认透明的浅色闭合音波、粉色搭配和用户设置的 1.5× 幅度。网易云音乐当前播放《遇上你之前的我》（Gareth.T）；未改变播放器的曲目、进度、音量或播放状态。窗口显示「只跟人声」与有效声音响应，随后关闭预览、保留桌面实例运行。
- 60 秒诊断共 599 次采样，429 次模型就绪、365 次人声 presence > 0.5；开始约 17 秒尚无输入，此后真实声音进入。人声能量 0–0.650、缩放 1–1.213、姿态高度 0–0.233、音波驱动 0–0.910、人声频谱最大值 0–0.932。内部捕获时间戳到姿态峰值 100.5 ms，分析通常约 4.9 ms；未包括 SceneKit 插值和显示扫描，不作完整 <150 ms 或歌曲逐句准确率结论。
- 全分析链测试约 0.704 秒处理 1.067 秒合成音频。实际音频没有写文件或上传，诊断只保留本地标量。人声分离仍可能漏入伴奏，真实歌曲是否跟得舒服由用户继续试听，实体输出设备切换仍沿用未验收状态。

## v0.8.0 · 音量驱动大小动作与彩色音波

用户要求人声变强时突然放大、跳得更大，变轻时收小；同时结合鼓点，并把彩色频谱、网格和音波流线放到角色背景。本版按这一要求调整，不把此前的「长音保持」解释为保持旧的音量峰值。

- 人声当前包络经过固定参考的幂曲线决定动作幅度和全角色等比缩放；耳机、墨镜随身体一起缩放。延音保留舒展方向，音量变小会收小动作。鼓点可有限叠加：普通唱句取最多 30% 的鼓点力度，可靠延音和换气时减轻，不叠加另一套周期舞步。
- 复用既有 512 样本 Hann FFT，生成 24 段绝对音量频谱；分离的人声和鼓声也分别提供频谱。`SoundField` 保存 96 个、30 Hz 的包络值（约 3.2 秒），桌面与预览共享同一状态。Canvas 以青色绘制人声包络、粉色绘制鼓声包络，并绘制频谱光环、网格和色块；没有随机条柱或独立动画时钟。
- Release XCTest：**68 项全部通过**，约 5.89 秒。新增真实频率与频谱位置、大小声差别、低声到大声时 8 帧内的大小／位移响应、长音渐弱、鼓点有限叠加、音波历史／暂停，以及 SceneKit 中身体和配饰一起放大且保持球形的检查。长音和换气的旧测试改为验证人声方向不会被鼓点带跑，允许用户新要求的有限加力。
- 此次完整分析链处理 1.067 秒合成音频约需 **0.551 秒**。相比早前较慢的样本有所不同，但没有隔离系统负载或证明持续实时性能；它不是端到端延迟或真实歌曲跟随准确率。
- v0.8.0 / build 11 先构建到 `dist/staged/Miho.app`，严格本地签名通过；构建脚本可用 `MIHO_APP_PATH` 指定独立输出位置。收到用户「重启、重新启用一次」后，通过现有菜单退出旧实例，保留旧应用备份，替换到 `dist/Miho.app`，只启动一个实例，捕获恢复且没有新的权限请求。

## v0.7.0 · 人声与延音主导

用户实际试听后再次否定 v0.6 的观感，明确要求跟随歌手的人声并保留延音。本版将伴奏节拍从主导姿态改为无人声时的小幅补充；旧版节拍测试通过不代表本次需求已经验收。

- 分离后人声增加全频段音量包络，起／落平滑时间常数约 25／100 ms，气声和缺少稳定音高的短音节仍可驱动姿态。音高与延音继续要求周期性证据。
- 人声包络、唱腔和延音决定主要姿态。唱句及短暂换气期间不再运行独立伴奏循环，也不因鼓点削弱人声幅度。人声重音触发力度，同时出现的鼓点最多轻轻加强 8%。无人声的伴奏目标幅度为旧版的 30%。
- 延音计时在重新起音时重置；唱句持续时间本身不再当作长音证据，短句力度不会永久锁在整段唱句的峰值。
- `./scripts/test.sh -c release`：**62 项 XCTest 全部通过**。新增／调整：同一人声在不同伴奏速度下姿态一致；长音和短暂换气不受无关鼓点干扰；人声重音不被节拍时钟压低；同音高反复音节不累积成假长音；短句音量起落仍有可见运动。原有五秒长音保持、音高升降、收句、受限惯性、原生模型一致性、伴奏跟拍及生命周期测试保留。
- Release `.app` v0.7.0 / build 10 构建与严格本地签名验证通过。两份模型和原生运行库仍随应用打包，运行时不依赖联网。

## v0.6.0 · 实际节拍模型与连续律动

前版被用户指出快节奏说唱、hip hop 和 rock 跟随不佳。这是新的实现与验证记录，旧版测试通过不代表该观感问题已通过验收。

- 真正接入 BeatNet model-2 CRNN；权重与转换图固定校验和，图随仓库／应用分发。上游滤波器与生成的 136 个滤波器逐项一致；30 个连续状态帧的 PyTorch／ONNX 输出差异低于 2e-6；原生 1411 点 FFT、特征和递归输出与独立 Python 结果一致，重置后可复现。
- `./scripts/test.sh -c release`：**58 项 XCTest 全部通过**。新增 88／124／174 BPM 解码、碎拍／短填充不改速度、半拍错位恢复、持续说唱不抑制律动、暂停回落，以及最终身体点头对拍和速度／加速度边界。
- 最终姿态对拍测试中，三个速度的连续点头峰值与预设拍子的偏差小于 100 ms。此测试输入是合成的节拍概率，不能代表真实歌曲识别精度或完整声音到显示延迟。
- 自写身体轨迹共享学到的相位；相位提前补偿惯性，快歌身体起伏可取半速，躯干点头保持每个跟踪到的拍子；换重心取更慢的两拍周期。人声独立叠加，不按预置舞步定时切换。
- Release `.app` 构建、`codesign --verify --deep --strict` 通过；运行库路径只含相对应用路径。使用打包的应用直接分析音频文件，确认两份模型和 SDK 可从应用内加载。
