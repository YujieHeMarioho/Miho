# 音乐跟随方案的选择

2026-10-01 调研。用户要求长音可以持续舒展与保持，动作由当前歌唱控制，不能被固定舞步的结束时间拉回原位。

| 方案 | 可用能力 | 本项目的选择 |
| --- | --- | --- |
| [BeatNet](https://github.com/mjhydri/BeatNet) | 流式 CRNN 和粒子滤波跟踪拍点、强拍 | 单独拍点不足以区分歌声与伴奏；本版没有集成 BeatNet，鼓点使用分离后的瞬态 |
| [HS-TasNet](https://arxiv.org/abs/2402.17701) | 低延迟实时音乐源分离研究 | 提供流式分离的研究依据 |
| [StemgenRT-5.8](https://github.com/sweetspotsoundsystem/StemgenRT-5.8) / [原生插件](https://github.com/sweetspotsoundsystem/stemgen-rt) | 可下载的 MIT 模型；44.1 kHz 立体声、128 样本跳长、八份状态 | 实际接入模型，自写 C++ 宿主和 Swift 后台分析；未安装 DAW 插件 |
| [EDGE](https://github.com/Stanford-TML/EDGE) | 从音乐生成完整人体舞蹈 | 离线生成路径和人体骨架不适合当前桌面球形角色的低延迟持续交互 |
| [LODGE](https://github.com/li-ronghui/LODGE) | 层次化长时音乐舞蹈生成 | 同样需要模型生成与人体动作表示，本版不采用 |

实际实现是人声分离加连续姿态控制，不宣称覆盖所有音乐跟随算法，也不宣称使用了生成式 AI 编舞。

每个唱句保存自己的起始音高。持续的人声决定姿态的展开，相对音高决定抬升／下落，力度决定幅度；同一长音期间不运行左右循环。短促重音叠加受限的物理响应，随后回到当前唱腔的姿态。句子真实结束后才释放方向与音高参考。动作仍有身体和窗口的物理范围限制。

模型漏音、合唱和音高估计错误会影响跟随。测试区分信号路径正常、动作逻辑正确和实际歌曲的观感；前两项不能代替最后一项。
